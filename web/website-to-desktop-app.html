WINDOWS + LINUX

A website as a Windows or Linux app.

URL to App wraps an HTTPS site in a small Tauri shell. The URL, app name, icon and window size are data, so the browser can assemble a per-site package without compiling a new binary. The desktop targets reuse the shell-plus-data model that started on Android.

What you get

  • Windows: a per-app Setup.exe with a current-user or all-users install, and a portable .zip.
  • Linux: a Flatpak, a system-WebKit AppImage and a .tar.gz, with x86_64 and aarch64 builds.
  • Flatpak first: the shared GNOME runtime supplies WebKitGTK, so security updates do not require rebuilding each generated app. The builder downloads a self-installing script that checks Flatpak and the runtime before installing the per-site archive.
  • Isolation: each app gets its own window title, shortcut, icon and WebView profile.

How the browser assembles it

The Windows portable build patches the PE icon and version resources. The installer appends a config payload to the NSIS setup. The Flatpak OCI archive is rewritten in the tab with a URL-derived app ID, desktop entry, icon and sidecar config; every OCI digest is recomputed. The AppImage uses a small Rust/WASM repacker to replace the embedded desktop entry and icon, then appends the same config trailer. The tar and zip are written with the right file modes.

The shell binaries are built once in CI and published as versioned static assets. The browser fetches the selected base, verifies its SHA-256 digest, patches it and downloads the result. Nothing is compiled for your site.

Install it

  1. Open the builder and choose Windows or Linux.
  2. Pick the architecture and package type.
  3. Generate the package. The shell is downloaded on demand.
  4. On Windows, run Setup and clear the SmartScreen warning. On Linux, run the downloaded Flatpak installer (chmod +x then ./<file>); it checks Flatpak and the GNOME runtime, then installs the per-site archive. Alternatively, chmod +x the AppImage or extract the tarball.

What it is not

  • Desktop packages are unsigned and will trigger SmartScreen on Windows.
  • There is no auto-update for the generated shell. Regenerating the app is the update path; the Flatpak runtime updates WebKitGTK independently.
  • The Flatpak installer needs Flatpak 1.18+ and the GNOME 50 runtime. The system-WebKit AppImage still needs FUSE; the tarball and --appimage-extract-and-run are the fallbacks.
  • macOS is not supported yet.
  • The app loads the live URL and has no offline copy.

If you want a compile-time Tauri or Electron build with your own plugins and updater, use Tauri CLI or Electron Forge directly. URL to App is for wrapping a live site with no toolchain and no per-site compiler run.
